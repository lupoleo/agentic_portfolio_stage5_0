# S5.0-3 — Claude replaces Ollama

`ClaudeProvider` (app/ai/claude_provider.py) implements the unchanged
`AIModelProvider` interface, so research, company assessment and scoring keep
their 4.0 contracts (`AIRequest` → `AIResponse`).

| Aspect | Behaviour |
|---|---|
| Routing | RELEVANCE, TRIAGE, CLASSIFICATION, SENTIMENT, EXTRACTION → `claude-haiku-5-5`; RESEARCH, REASONING → `claude-sonnet-5-5` (configurable, `task_overrides` for e.g. `claude-opus-5-5`) |
| Effort | `ReasoningMode.FAST` → `low`, `REASONING` → `high` (adaptive thinking) |
| JSON | requests with `output_schema` use structured outputs (`messages.parse`) and are re-validated with the same Pydantic model |
| Fallback | server-side fallback (`fallbacks="default"`) on Sonnet/Opus; the model that actually answered is stored in `AIResponse.model` |
| Failures | refusal, truncation, timeout, connection, HTTP and validation errors are typed; nothing is invented |
| Data policy | only `DataSensitivity.PUBLIC` requests leave the machine (G8) |

Runtimes (`app/e2e/stage4_runtime.py`, `stage4_replenishment_runtime.py`) and
the main E2E CLIs now build the provider through `app/ai/provider_factory.py`.
Default model `claude-sonnet-5-5`; `ollama:<model>` still selects the local
provider for comparison runs. Credentials: `ANTHROPIC_API_KEY` (or an
`ant auth login` profile) on the machine that runs the pipeline.

Not yet migrated: the 4.0 diagnostic scripts under `tools/live_*` that create
`LocalProvider("qwen3:8b")` directly, and the Ollama checks in
`tools/stage4_validation.py preflight`. They are replaced when the IBKR
evidence providers land (S5.0-4).
